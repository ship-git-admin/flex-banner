# 実装計画: カスタム権限によるロール管理 (v2.4.0)

## 1. 目的
- プラグインが「管理者」に対してのみ確実にサイドバーに表示され、「それ以外のロール」からは確実に消えるようにする。
- 同時に、プラグイン側が一時的にメニューを消し飛ばしてしまうような脆い実装を避け、WordPress標準のロール・権限付与メカニズムに沿った安全な手法を採用する。

## 2. 実装手法
1. **専用のCapability Type**: カスタム投稿タイプの権限群を `post` から専用の `flex_banner` に切り離します。
2. **データベース上の明示的付与**: `get_role('administrator')->add_cap(...)` を用いて、独立させた権限を管理者ロールのデータベースデータに直接追加します。
    - 以前の「フィルタリング手法（map_meta_cap等で強引にmanage_optionsを返すだけ）」は他プラグインと競合してメニュー表示が壊れやすいため、今回は破棄し、ロール自体に具体的な権限を与えます。
3. **自動適用**: ユーザーが操作しなくても、`admin_init` フックとバージョン値を比較して自動的に権限を付与するルーチンを実装します。

## 3. これによるメリット
- メニューの表示/非表示判定がWordPressのコア関数で自然に行われるため、バグりにくく安定します。
- User Role Editor などの外部ツールから見ても、「flex_banner を編集」という明確な権限項目が確認できるようになり、管理が明瞭になります。
